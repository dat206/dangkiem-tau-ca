Data Flow — Parse DOCX → Excel

1. Input DOCX — Giấy CN An toàn KT tàu cá gồm các field quan trọng:

Số đăng ký → QN-90599-TS (tỉnh + số)
Chủ tàu → Họ và tên chủ
Địa chỉ → Xã/phường, tỉnh
Công dụng (nghề) → Lưới rê, chụp...
Vật liệu → Gỗ / Thép / FRP
Lmax → Chiều dài (m)
Ne (KW) → Công suất máy
Cấp tàu → Không hạn chế / Hạn chế I/II/III
Hình thức KT → Hàng năm / Định kỳ / Trên đà...
Ngày hiệu lực → Hạn đăng kiểm

2. Business Logic — Phân nhóm theo Lmax (12-15m, 15-20m, 20-24m, 24-30m, ≥30m), phân loại vật liệu, đếm theo hình thức kiểm tra, nhóm theo tỉnh từ mã đăng ký.

3. Output Excel — 2 file: Bảng kê tổng hợp (mỗi tàu 1 dòng) và Báo cáo quý (nhiều sheet theo tỉnh, bảng thống kê).

#001b Khởi tạo PostgreSQL schema trên Neon.tech + migration với Alembic Trung bình ▶
User Story
Là developer, tôi muốn có database PostgreSQL thực sự trên cloud, được version-control bằng Alembic, để schema luôn đồng bộ giữa local và production mà không cần sửa tay.
Mô tả

Đầu ra

✅ Có thể rollback bằng alembic downgrade -1
✅ DATABASE_URL không hardcode trong code, đọc từ env
Tại sao dùng Alembic thay vì Base.metadata.create_all()?
Alembic version-control schema như Git version-control code. Sau này thêm cột mới, đổi kiểu dữ liệu → chỉ cần tạo migration mới, không cần xóa DB làm lại. Đây là kỹ năng production thực tế cực giá trị cho CV.
